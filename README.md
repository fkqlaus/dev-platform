# Dev Platform

**이미 사용하는 SSH Git 서버에, 이름만 입력해 새 저장소를 만드세요.**

서버에 접속해서 폴더를 만들고 `git init --bare`를 실행하던 작업을 로컬 웹 화면으로 옮겼습니다. Git 서버 설치 도구가 아닙니다. 기존 Git 서버와 생성 권한이 있는 계정이 필요합니다.

[빠른 시작](#빠른-시작) · [실행 전 확인](#실행-전에-알아둘-점) · [배포본 만들기](#배포본-만들기)

## 무엇을 할 수 있나요?

| 연결 | 확인 | 생성 |
|---|---|---|
| 기존 프로젝트의 SSH 주소에서 서버 정보 가져오기 | 서버 키 지문, 인증, 실행 계정, 경로 권한 검사 | 프로젝트 이름으로 bare 저장소 생성 |
| 직접 실행 또는 sudo 선택 | 변경된 서버 키 차단 | clone 주소와 기존 프로젝트 연결 명령 안내 |

서버에 별도 에이전트나 생성 스크립트를 설치하지 않습니다. 기존 경로는 재초기화하거나 삭제하지 않습니다. 실패 후 새로 만들어진 폴더도 자동 삭제하지 않습니다.

## 빠른 시작

### A. 소스로 직접 실행 — 기본 사용 경로

소스를 검토하고 직접 실행하려는 개발자를 위한 방법입니다. **JDK 21**이 필요하며, Gradle은 따로 설치하지 않아도 됩니다.

소스를 내려받아 압축을 풀고 프로젝트 폴더에서 실행하세요.

**Windows / PowerShell**

```powershell
.\gradlew.bat bootRun
```

**macOS / Linux**

```bash
sh gradlew bootRun
```

[http://localhost:8080](http://localhost:8080)을 엽니다. 첫 빌드는 Gradle과 의존성 다운로드를 위해 인터넷이 필요합니다. 8080이 사용 중이면 `bootRun --args="--server.port=18080"`처럼 바꿀 수 있습니다.

### B. Java가 포함된 배포본 — 설치 편의용

운영체제와 CPU에 맞는 패키지를 압축 해제한 뒤 실행합니다. 시스템에 Java를 설치하거나 `JAVA_HOME`을 변경할 필요가 없습니다.

| 운영체제 | 실행 파일 |
|---|---|
| Windows x64 | `DevPlatform/DevPlatform.exe` |
| macOS Intel / Apple Silicon | `DevPlatform.app` |
| Linux x64 / ARM64 | `DevPlatform/bin/DevPlatform` |

빈 로컬 포트로 시작한 뒤 브라우저를 엽니다. 자동으로 열리지 않으면 데이터 폴더의 `running-url.txt` 주소를 사용하세요. 종료는 화면의 **앱 종료** 버튼으로 합니다. 브라우저 탭을 닫는 것만으로 서버가 종료되지는 않습니다.

**현재 배포 구성은 서명되지 않은 미리보기입니다.** 이 저장소에는 패키지 생성 워크플로가 있으며, 아직 공개 GitHub Release나 모든 OS의 실행 성공을 주장하지 않습니다. OS가 실행을 차단한다면 보호 기능을 일괄 해제하지 말고 소스 빌드 경로를 이용하세요. [직접 패키지 만드는 방법](#배포본-만들기)

## 첫 저장소 만들기

1. **기존 Git 주소 입력** — 예: `ssh://git@server.example:22/repos/project.git`.
2. **생성 계정 설정** — 평소 새 저장소를 만들 때 사용하는 SSH 계정과 비밀번호를 입력합니다. push 계정과 다를 수 있습니다.
3. **실행 방식 선택** — 접속 계정이 직접 생성하거나 sudo로 다른 계정 권한을 사용합니다. 그룹은 선택 사항입니다.
4. **서버 키 확인** — 조회된 지문을 관리자 또는 서버 콘솔에서 확인한 값과 비교하고 승인합니다.
5. **연결·권한 검사 후 저장** — 별도 known_hosts 파일은 필요하지 않습니다.
6. **프로젝트 이름 입력** — 생성된 주소로 clone하거나 기존 프로젝트에 remote를 추가합니다.

프로젝트 이름은 영문·숫자로 시작하는 1~64자의 영문·숫자·하이픈·밑줄입니다. `.git`은 자동으로 붙습니다. 실제 clone·push는 개발 PC의 Git으로 별도 확인하세요.

## 실행 전에 알아둘 점

- **자격증명:** SSH·sudo 비밀번호는 로컬 설정 파일에 평문으로 저장됩니다. 파일은 소유자 전용 권한을 적용하지만 암호화 저장소는 아닙니다. 설정·로그를 공유하지 마세요.
- **권한:** sudo 모드는 대상 계정으로 `/bin/sh`를 실행합니다. ‘저장소 생성만 가능한 권한’으로 제한된 구조가 아닙니다.
- **통신:** 제품 코드에 분석·광고·업데이트 확인 기능은 없습니다. 입력한 서버에 SSH 연결하며 브라우저는 로컬 앱에 연결합니다. 소스 빌드의 의존성 다운로드와 OS의 인증서·보안 검사는 별개입니다.
- **신뢰:** 소스 공개, 빌드 로그, 메타데이터는 검토 근거입니다. 배포 파일의 안전이나 비트 단위 재현성을 보증하지 않습니다.

생성은 이름·경로·계정을 검증한 뒤 `mkdir`로 경로를 선점하고 `git init --bare`를 실행합니다. sudo 비밀번호는 명령 인자가 아닌 표준입력으로 전달합니다. 응답이 끊기거나 시간이 초과되면 서버에 저장소가 이미 생성됐을 수 있으므로, 재시도 전에 확인하세요.

## 설정은 어디에 있나요?

| 실행 방식 | 설정 위치 |
|---|---|
| 소스 / 일반 JAR | 실행 폴더의 `config/connection.properties` |
| Windows 배포본 | `%LOCALAPPDATA%\DevPlatform\connection.properties` |
| macOS 배포본 | `~/Library/Application Support/DevPlatform/connection.properties` |
| Linux 배포본 | `${XDG_DATA_HOME:-~/.local/share}/dev-platform/connection.properties` |

배포본은 프로그램 폴더를 교체해도 사용자 설정을 유지합니다. 기존 소스 실행의 설정을 자동 복사하지는 않습니다. 배포본 첫 실행에서 새로 연결하세요. 경로는 화면에도 표시됩니다. 연결 설정을 초기화하려면 앱을 종료한 뒤 해당 `connection.properties` 파일을 삭제하세요. 서버의 Git 저장소는 삭제되지 않습니다.

## 지원 범위

| 지원 | 아직 지원하지 않음 |
|---|---|
| 기존 Linux·NAS SSH bare 저장소 | Git 서버 설치·계정 생성·권한 자동 부여 |
| SSH 비밀번호 인증, 선택적 sudo | SSH 개인키·에이전트 인증 |
| 절대 경로의 SSH URL 및 `user@host:/path/repo.git` | 상대 경로, IPv6, HTTPS, GitHub/GitLab/Gitea API |
| 한 PC에서 사용하는 로컬 도구 | 공유 웹 서비스의 로그인·사용자별 권한 |

서버 경로는 영문·숫자·하이픈·밑줄로 구성된 절대 경로를 지원합니다. macOS/Linux 패키지 빌드 구성이 있다는 것과 해당 OS에서 검증됐다는 것은 다릅니다. Windows 배포본 실행은 확인했으며, macOS/Linux와 GitHub Actions의 실제 실행은 아직 확인하지 않았습니다.

## 개발과 기여

```powershell
.\gradlew.bat test bootJar
```

테스트는 임시 SSH 서버를 사용하며 실제 회사 서버에 접속하지 않습니다. PR에는 변경 이유, 영향 범위, 실행한 검증을 함께 적어주세요. 버그 제보에서 비밀번호·서버 키 지문·내부 주소를 제거해 주세요.

Java 21 · Spring Boot 4.1.1 · Apache MINA SSHD · Thymeleaf

## 코드 구조와 확장 방향

현재는 DB 없이 동작하는 로컬 도구입니다. 연결 설정은 파일로 저장하며, 실제 Git 저장소는 사용자가 지정한 서버에 생성합니다.

| 패키지 | 책임 |
|---|---|
| `project` | 프로젝트 생성 요청·응답과 진행 |
| `connection` | 연결 설정 선택·파일 저장·서버 키 승인 |
| `git` | 저장소 생성 명령과 결과 검증 |
| `ssh` | SSH 접속·인증·명령 실행과 클라이언트 종료 |
| `web` | 홈 화면·공통 오류 응답·로컬 요청 보호 |
| `desktop` | 런타임 동봉 배포본의 시작·중복 실행 방지·종료 |

설정 방식과 관계없이 같은 Git 생성기를 사용합니다. 현재 단일 사용자 용도에서는 SSH 작업을 순차 실행하여 요청 간 서버 키 검증이 섞이지 않도록 합니다.

초기 코드 템플릿, CI/CD 구성, 개발 서버 배포, 프로젝트별 사용자 권한은 **향후 목표이며 아직 구현하지 않았습니다.** 현재 기능에 필요하지 않은 계층이나 워크플로 엔진은 미리 도입하지 않습니다.

## 배포본 만들기

빌드에는 JDK 21과 Python 3.12 이상이 필요합니다. `JAVA_HOME`은 해당 JDK를 가리켜야 합니다. 대상 운영체제·CPU와 일치하는 환경에서 실행하세요.

```sh
python scripts/package.py
python scripts/smoke-package.py
```

첫 명령은 테스트와 JAR 빌드 후 Java 런타임을 포함한 압축파일을 `build/distributions`에 만듭니다. 두 번째 명령은 실제 실행 파일로 설정 유지·중복 실행 방지·종료를 확인합니다. 합성 설정을 사용하며 실제 Git 서버에 저장소를 생성하지 않습니다.

GitHub Actions는 PR 또는 수동 실행 시 OS별 패키지와 검사 결과를 artifact로 보관합니다. Release를 자동 게시하지 않습니다. 로컬에서 실행한 Windows 검사는 다른 OS의 성공이나 서명·공증을 보장하지 않습니다.
